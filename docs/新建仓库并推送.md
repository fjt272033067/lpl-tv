# 新建仓库并推送 —— 可复用流程（含本机实测结论）

> 本文所有结论均在本机实测过（Windows + Git 2.52 + 中国内地电信 + Watt Toolkit 加速环境）。
> 2026-10-30 实测更正过一次早期误判：问题不在加速器，而在 **owner 拼写错误**。

---

## 0. 先做这一步：核对仓库真实全名

GitHub API 匿名可查，**不要凭记忆写账号名**：

```bash
# 账号是否存在（404 = 名字写错了，不是私有、不是限流）
curl -s https://api.github.com/users/<owner>
# 仓库是否存在、是否 Public
curl -s https://api.github.com/repos/<owner>/<repo>
# 名字拿不准时反查
curl -s "https://api.github.com/search/repositories?q=<repo>+in:name"
```

> GitHub 对「**不存在**」和「**存在但你无权限**」的仓库一律返回 **404**（刻意设计，防止探测私有仓库）。
> git 会把 404 翻译成 `Repository not found` —— **这几乎总是「owner 拼错」或「账号没权限」，不是网络问题。**

---

## 1. 新建仓库时的选项

| 选项 | 该怎么选 | 原因 |
|---|---|---|
| Repository name | 你的目标名 | |
| **Public / Private** | 取决于是否要**匿名读取**（见下） | 站点要匿名拉 raw JSON → **必须 Public**；私有仓的 raw 匿名请求一律 404 |
| **不要勾** README | 不勾 | 勾了远端会有初始 commit，与本地历史无共同祖先 → push 被拒 |
| **不要勾** .gitignore | 不勾 | 同上；本地的 .gitignore 才是权威 |
| **不要勾** LICENSE | 不勾 | 同上（本地想加再加） |

## 2. 推送：两条路

### 路径 A · HTTPS（通用，换任何机器都能用）

```bash
cd <项目目录>
git remote add origin https://github.com/<owner>/<repo>.git
git branch -M main
git push -u origin main
```

- 首次 push 会弹**浏览器授权窗口**（Git Credential Manager），点一下授权，凭据会被记进 Windows 凭据管理器，之后不再弹。
- 不想用浏览器授权，就改用 **fine-grained PAT**（仓库 → Settings → Developer settings → Personal access tokens，勾 `Contents: Read and write`）。
- 已有 remote 要改地址：`git remote set-url origin <新地址>`。

### 路径 B · SSH（本机已配好，更省事，无需浏览器）

本机 `~/.ssh/config` **已经配好**（见下方附录），换任何项目都直接用：

```bash
cd <项目目录>
git remote add origin git@github.com:<owner>/<repo>.git
git branch -M main
git push -u origin main
```

公钥必须注册在**拥有该仓库的那个账号**下 —— 加错账号的表现和 owner 拼错一模一样（404 → Repository not found）。

## 3. 推送后自检

```bash
git ls-remote origin                      # 能列出 refs = 链路 + 地址 + 权限都 OK
git log --oneline -1 origin/main          # 远端 HEAD 和本地一致
```

如果 `git ls-remote` **列不出来**：

| 报错 | 含义 | 怎么办 |
|---|---|---|
| `Repository not found` | owner 拼错 **或** 该账号无此仓库权限 | 回第 0 步核对名字 |
| `could not read Username ... terminal prompts disabled` | 缺凭据（非交互 shell 专有） | 在交互终端里跑，或用 SSH |
| `Invalid username or token` | 凭据无效/过期 | 删掉旧凭据重新授权，或改用 SSH |
| 连接超时 | 网络/加速器问题 | 见下方「本机网络注意事项」 |

## 4. 本机网络注意事项（内地电信 + Watt Toolkit）

本机 `hosts` 把 `github.com` / `api.github.com` / `raw.githubusercontent.com` 等
全部指向 `127.0.0.1`，**Steam++ 同时监听 80 和 443 并正确代理 HTTPS** ——
实测开着加速器 `git ls-remote` 对公开仓库**能正常返回 refs**，所以
**git 报错不要先归咎加速器**。

- 需要**真直连** GitHub（大仓库 clone、release/大文件下载）时，
  **先提示使用者退出 Watt Toolkit**；**下载优先走国内镜像源**（ghproxy、npmmirror、gitee 镜像、gitclone）。
- `ssh.github.com` 不在 hosts 名单里，能直连（22 / 443 均通），属于**直连**——大流量推送会很慢，用之前先说明。

## 5. 如果新项目也要「站点自动读远端数据」

光推代码不够，还要让**站点**指向这个仓库：

```bash
node tools/set-data-base.mjs https://raw.githubusercontent.com/<owner>/<repo>/main/site/data
node tools/stamp-assets.mjs          # 给资源 URL 挂内容哈希戳，绕开 CDN 的旧缓存
# 然后重新部署 site/ 目录
```

CDN 选型要求（实测）：

| 托管 | 缓存策略 | 结论 |
|---|---|---|
| `raw.githubusercontent.com` | `max-age=300` + `ACAO: *` | ✅ 20 分钟级更新用这个 |
| `cdn.jsdelivr.net` / `fastly.jsdelivr.net` | `s-maxage=43200`（**12 小时**） | ❌ 分支 URL 下缓存半天，看起来像「数据没更新」 |

站点侧设计：本地快照与远端两份都读，按 `updatedAt` 取更新的那份；**远端探测放后台不 await**，
拿不到就静默回退本地 —— 首屏永不被外部依赖卡住。

## 附录 · 本机 SSH 现有配置

`C:\Users\Administrator\.ssh\config`：

```
Host github.com
    HostName ssh.github.com
    User git
    Port 443
```

新建密钥（**不要**覆盖已有的 `id_ed25519`）：

```bash
ssh-keygen -t ed25519 -C "<你的标签>" -f "$env:USERPROFILE\.ssh\id_ed25519_<新项目>"
```

公钥内容：

```bash
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

注册：GitHub → **Settings → SSH and GPG keys → New SSH key**，
**必须加在拥有该仓库的账号下**。
