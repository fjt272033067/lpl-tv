| 名字 | 是什么 | 本项目的值 |
|---|---|---|
| **工作目录** | 电脑上放代码的文件夹 | `E:\M3.1-Flash工作室\lpl-tv` |
| **GitHub 仓库** | 代码的云端备份，同时托管赛事数据 | `github.com/fjt272033067/lpl-tv`（**公开**） |
| **线上站点** | 用户看到的网页 | `https://4kf9kfxujfhg2.space.mcode.cn` |

一句话看懂整条流水线：

```
你改代码
   │
   ├─ git commit   存一次档（只在本地）
   │
   └─ git push     上传到 GitHub
          │
          ├─→ GitHub 自动跑 CI，重新抓一遍赛事数据推回仓库
          │      └─→ 线上站点 1 分钟内自动显示新赛程 / 新流地址

          └─→ 只有改了网页文件（HTML / CSS / JS），才需要「重新发布站点」
```

**最需要记住的一条**：改赛事数据、赛程、直播源 —— **不用重新发布站点**，CI 会自动更新。
改了网页本身的代码 —— 才要重新发布。

## 1. 一次性准备（只做一次）

### 1.1 确认 Git 装好了

```powershell
git --version
```

输出 `git version 2.52.0.windows.1` 之类就说明装好了。

### 1.2 确认提交身份

```powershell
git config user.name
git config user.email
```

本项目已配好：`方晨` / `287671633+fjt272033067@users.noreply.github.com`。
换人操作要改：

```powershell
git config user.name "你的名字"
git config user.email "你的邮箱"
```

> 第一次推送如果提示 `Please tell me who you are`，就是这里没配。

### 1.3 确认仓库地址

```powershell
git remote -v
```

应该看到：

```
origin  git@github.com:fjt272033067/lpl-tv.git (fetch)
origin  git@github.com:fjt272033067/lpl-tv.git (push)
```

地址写错就改：

```powershell
git remote set-url origin git@github.com:fjt272033067/lpl-tv.git
```

> ⚠️ 用户名 `fjt272033067` **少一个字母**（`fj` → `fjt`）就会报 `Repository not found`，
> 这跟网络、跟权限都没关系，就是拼错了。

### 1.4 要不要再登录？

本机用的是 **SSH 方式**，密钥已经注册好了，正常情况**不用再登录**。
换新电脑或密钥失效时，GitHub 网页上换用 HTTPS 地址会弹一次浏览器授权窗口，点一下「授权」即可。

## 2. 日常迭代：改了东西怎么提交上去 ⭐ 最常用

### 第 1 步 · 进入项目目录

```powershell
cd "E:\M3.1-Flash工作室\lpl-tv"
```

### 第 2 步 · 看看你改了什么

```powershell
git status --short
```

输出长这样：

```
 M site/assets/app.js
 M site/index.html
?? site/assets/new-feature.js
```

- `M` = 修改了已有文件
- `??` = 新文件，还没纳入管理

**这一步别跳过**。看清楚再提交，能避免把不该提交的东西推上去。

### 第 3 步 · 把要改的文件放进「待提交清单」

```powershell
git add site/assets/app.js site/index.html
```

- **只写你真正改过的文件**，中间用空格隔开
- 不知道文件叫什么，就回第 2 步看 `git status --short`
- ⚠️ **不要用 `git add .`** —— 它会把文件夹里所有东西都加上，包括临时文件、大图片

### 第 4 步 · 存一次档

```powershell
git commit -m "fix: 修复清晰度菜单点不开的问题"
```

引号里写清楚改了什么，以后好查。建议格式 `类型: 说明`：

| 类型 | 用在什么时候 |
|---|---|
| `fix` | 修 bug |
| `feat` | 新功能 |
| `docs` | 改文档 |
| `data` | 只更新了数据文件 |

> 提交信息里别写「更新」「修改」这种没信息量的词 —— 出问题时要靠它定位。

### 第 5 步 · 上传到 GitHub

```powershell
git push origin main
```

第一次成功后 Git 会记住这个习惯，以后直接 `git push` 也行。

### 第 6 步 · 确认真的传上去了

```powershell
git ls-remote origin refs/heads/main
git rev-parse HEAD
```

两条命令打印的**哈希值一样**，就说明本地和云端完全同步了。

### 第 7 步 · 等 CI 干活（1~3 分钟）

打开仓库的 Actions 页面看最新一条是不是绿勾：

```
https://github.com/fjt272033067/lpl-tv/actions
```

绿勾 = 赛事数据已重新抓取并推回仓库，线上站点会自己更新，不用管。

## 3. 推送被拒绝了怎么办（最常见的一种）

### 现象

```
! [rejected]        main -> main (non-fast-forward)
error: failed to push some refs to 'github.com:fjt272033067/lpl-tv.git'
```

### 原因

云端已经有了你本地没有的新提交。**最常见的来源就是 CI**：CI 每跑完一次会自动提交一份新的赛事数据，
正好撞上你要推送的时刻。

### 解决：先拉取，再推送（两条命令）

```powershell
git pull --rebase origin main
git push origin main
```

`--rebase` 的意思是「把你的改动接在云端最新提交后面」，不会多出一条没用的合并记录。

### 如果出现了冲突

```
CONFLICT (content): Merge conflict in site/assets/app.js
```

说明你和云端改了同一个文件的同一处。处理办法：

```powershell
git status                                  # 看哪些文件冲突
# 打开冲突文件，把 <<<<<<< / ======= / >>>>>>> 三段标记删掉，保留正确内容
git add site/assets/app.js                   # 标记为已解决
git rebase --continue                       # 继续
git push origin main
```

实在搞不定、想放弃这次推送：

```powershell
git rebase --abort
```

## 4. 报错速查表

| 报错里出现的字样 | 意思 | 怎么办 |
|---|---|---|
| `Repository not found` | 仓库地址里的用户名或仓库名写错了，**或**该账号没权限 | `git remote -v` 核对；应为 `fjt272033067/lpl-tv` |
| `could not read Username ... terminal prompts disabled` | 当前终端不让它弹窗要密码 | 换成一个正常打开的 PowerShell 窗口再试 |
| `Invalid username or token` | 凭据过期或无效 | 改用 SSH 地址：`git remote set-url origin git@github.com:fjt272033067/lpl-tv.git` |
| `fatal: refusing to merge unrelated histories` | 本地和云端是两套完全不同的历史 | 说明建仓方式不对，见 §5 |
| `non-fast-forward` / `rejected` | 云端有新提交 | 见 §3 |
| `nothing to commit, working tree clean` | 没有要提交的东西 | 正常，不用管 |
| `Please tell me who you are` | 没配提交身份 | 见 §1.2 |
| 连不上 / 超时 | 网络或加速器问题 | 见 §10 |

## 5. 万一要新建一个仓库（一次性流程）

### 5.1 在 GitHub 网页上建仓时的选项

| 选项 | 怎么选 | 为什么 |
|---|---|---|
| Repository name | 填目标名字 | |
| Public / Private | **Public** | 站点要匿名读取仓库里的赛事数据 JSON；私有仓库的匿名请求一律 404，站点就更新不了 |
| README | **不要勾** | 勾了远端会自带一个初始提交，和本地历史没有共同祖先，第一次 push 会被拒 |
| .gitignore | **不要勾** | 同上；本地那份才是权威 |
| LICENSE | **不要勾** | 同上（本地想加再加） |

### 5.2 本地六条命令

```powershell
cd "E:\M3.1-Flash工作室\lpl-tv"

git init                                                            # ① 把这个文件夹变成 Git 仓库
git add .                                                           # ② 把文件放进待提交清单
git commit -m "init: 首次提交"                                       # ③ 存一次档
git remote add origin git@github.com:fjt272033067/lpl-tv.git       # ④ 告诉 Git 上传到哪里
git branch -M main                                                  # ⑤ 主分支统一叫 main
git push -u origin main                                             # ⑥ 上传，并把 main 设为默认分支
```

第 ② 步之前先确认 `.gitignore` 里有这些（避免把密钥和大文件推上去）：

```gitignore
node_modules/
/data/
*.log
.env
.env.*
*.pem
*.key
.DS_Store
```

## 6. 提交之前的安全自检（30 秒）

```powershell
git status --short              # ① 有没有不该出现的文件（.env、node_modules、大图）
git log --oneline -5             # ② 最近 5 次提交写了什么
git diff --stat                  # ③ 这次改动涉及多少文件、多少行
```

另外记住 Git 的两条「不可逆」特性，新手最容易吃亏：

- **`git push` 推的是完整历史，不只是最后一次提交。** 本地所有提交过的内容都会公开；
  就算后来删掉文件，历史里的内容也还在。
- **`git branch -M main` 的大写 `M` = 强制改名**，会覆盖已有的 main 分支。
  只是想改个名字，用小写 `git branch -m`。

## 7. 改错了怎么撤销

| 想撤销什么 | 命令 | 注意 |
|---|---|---|
| 把某个文件从「待提交清单」里拿出来 | `git restore --staged site/assets/app.js` | 文件内容不变，只是不提交它 |
| 放弃某个文件**还没提交**的修改 | `git restore site/assets/app.js` | ⚠️ **改动直接没了，不可恢复** |
| 撤销上一次提交，但把改动留在工作区 | `git reset --soft HEAD~1` | 适合「提交说明写错了」 |
| 撤销上一次提交，连改动一起丢掉 | `git reset --hard HEAD~1` | ⚠️ **危险**，慎用 |
| 撤回**已经推上去**的提交 | `git revert <提交哈希>` | ✅ 最安全，生成一条"反提交" |

⚠️ 公开仓库上**不要**用 `git push --force` / `--force-with-lease`：
那会改写已经公开的历史，别人拉到的代码会错乱。用 `git revert` 就够了。

## 8. 站点发布：什么时候需要做

| 你改了什么 | 要不要重新发布站点 |
|---|---|
| 只有 `site/data/` 里的数据（赛程、录像目录、直播源） | **不用**。CI 自动抓新数据，站点自己会去读 |
| `site/index.html`、`site/assets/*.js`、`site/assets/*.css` | **要**。这些是网页本身，改完必须重新发布 |
| `tools/`、`docs/` 下的脚本和文档 | **不用**。不参与站点运行 |

### 发布前的必做一步：刷新资源哈希戳

```powershell
node tools/stamp-assets.mjs
```

它会给资源 URL 挂上内容哈希（比如 `app.js?v=e08b02fb8e`），用来绕开浏览器和 CDN 的旧缓存。
**漏了这一步，发布后用户看到的还是旧页面。**（这个命令可以重复跑，不会乱。）

然后把 `site/` 目录重新发布一次（桌面端发布工具，或让 AI 代劳）。

### 发布后自检（只读，不改任何东西）

```powershell
Invoke-WebRequest -Uri "https://4kf9kfxujfhg2.space.mcode.cn/index.html?t=$([DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds())" |
  Select-Object -ExpandProperty Content | Select-String -Pattern "v=[a-f0-9]{10}"
```

能搜到一个 10 位哈希戳，就说明线上已经是新版本了。

## 9. 定时刷新赛事数据（GitHub 自带定时器不可用时的替代办法）

**现状**：仓库里已经写好了定时任务（每 20 分钟跑一次），但 GitHub 对这个仓库**不执行**定时任务 ——
其它一切正常（手动触发能跑、推送能触发），唯独定时不跑，而且**不报错、不发邮件**。

所以目前数据靠「有人推送代码时顺带刷新」。要恢复正常，用一个外部定时服务（免费）每 20 分钟叫醒一次 GitHub。

### ① 建一个最小权限的令牌

打开 <https://github.com/settings/personal-access-tokens/new>：

- **Repository access** → Only select repositories → 只勾 `lpl-tv`
- **Repository permissions** → **Actions: Read and write**
- 生成后复制（`github_pat_...` 开头）→ **只粘到调度服务里，不要发到聊天里、不要提交进仓库**

### ② 在定时服务里加一条 HTTP 任务

cron-job.org / UptimeRobot / 一台小 VPS 的 crontab 都行，**不要用自己电脑常驻**。每 20 分钟执行一次：

```
POST https://api.github.com/repos/fjt272033067/lpl-tv/actions/workflows/refresh-data.yml/dispatches
Authorization: Bearer <你的令牌>
Content-Type: application/json

{"ref":"main"}
```

### ③ 本机手动验证这条通道通不通

```powershell
$env:GITHUB_TOKEN = 'github_pat_xxx'
node tools/dispatch-refresh.mjs
```

然后去 Actions 页面看有没有多出一条 run。

> **为什么 GitHub 定时任务不跑、怎么证明不是我们配错了**，完整排查过程见
> **附录-定时调度与数据通道排查.md**。

## 10. 本机网络提醒（内地电信 + Watt Toolkit）

本机 hosts 把 `github.com`、`raw.githubusercontent.com` 等域名指向 `127.0.0.1`，由 Watt Toolkit（Steam++）本地代理接管。

- 日常 `git push` / `git pull` / `git ls-remote` **开着加速器实测都正常** ——
  **报错了先别怪加速器**，先按 §4 的表对号入座。
- 需要 clone 大仓库、下载 release 或大文件时，**先退出 Watt Toolkit**，
  并优先用国内镜像（ghproxy、npmmirror、gitee 镜像）。
- 还有一个已知差异：**命令行能连通 `raw.githubusercontent.com`，但浏览器里可能连不上。**
  所以站点的数据通道配了多个镜像兜底，别只押一个源。

## 附录 A · SSH 配置（本机已配好）

`C:\Users\Administrator\.ssh\config`：

```
Host github.com
    HostName ssh.github.com
    User git
    Port 443
```

新建密钥（**不要**覆盖已有的 `id_ed25519`）：

```powershell
ssh-keygen -t ed25519 -C "<你的标签>" -f "$env:USERPROFILE\.ssh\id_ed25519_<新项目>"
```

查看公钥内容：

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

注册到 GitHub → **Settings → SSH and GPG keys → New SSH key**，
**必须加在拥有该仓库的那个账号下**（加错账号的表现和用户名拼错一模一样：都报 `Repository not found`）。
