# 总决赛跟赛功能（`/final.html`）

> 首版：2026-11-15（2026 全球总决赛 GEN vs BLG 期间上线）
> 适用：`site/final.html` + `site/assets/match.js` + `site/assets/match.css` + `site/assets/live-danmaku.js`

---

## 0. 一句话

给「一场正在进行的 BO5」单独做的一个**独立页**：实时比分（带来源标注）、**可解释的胜率条**（显示完整推导链）、
两队数据对比、自动看点解读、社群热词/情绪/里程碑。

**独立页，不引主站 `app.js`** —— 跟赛页的任何改动都不会波及主播放器，零回归风险。

---

## 1. 数据源（全部本机实测，2026-11-15）

### 1.1 实时比分 —— 主源是 **CI 烘焙的 `schedule.json`**

| 源 | 可用性 | 结论 |
|---|---|---|
| **镜像 `schedule.json`**（CI 每 20 分钟烘焙） | ✅ 浏览器实测 4/4 镜像可 fetch | **主源**。实测在比赛进行中更新到 `1:0`（CI 提交 `20:39 UTC`） |
| 腾讯 `LOL_MATCH2_LIVE_BMATCH_LIST.js` | ✅ `<script>` 可加载 | **备选**。腾讯的静态 .js 在边缘节点会**滞后**（实测同一时刻 `gh-proxy` 给 11-09 旧副本、`raw` 给 04:39 新副本） |
| 腾讯 `LOL_MATCH2_MATCH_HOMEPAGE_BMATCH_LIST*.js` | ❌ 浏览器读不到 | 是**裸 JSON**（没有 `var` 赋值），`<script>` 加载只会求值后丢弃；也没有 ACAO，`fetch` 读不了 |
| B 站直播间标题/描述 | ❌ `-352` 风控 / `ERR_FAILED` | 不可用 |
| 虎牙 / 斗鱼 | ❌ 无 ACAO、API 404 | 虎牙官网页面里有结构化比分卡（`title="GEN 0:0 BLG"`），但浏览器跨域读不到 |
| 手动指定 | ✅ | `?s=2:1` 或页面内点选，localStorage 记忆，**最高优先级** |

> ⚠️ **镜像的新鲜度不一致**：实测同一时刻 `gh-proxy` / `gcore` 给的是旧副本（`updatedAt` 停在 11-09），
> `cdn.jsdelivr` / `raw.gh` 给的是新的。页面**并发取全部镜像并按 `updatedAt` 挑最新** —— 这是必须的，
> 只押一个源会拿到陈旧比分。

### 1.2 直播源

腾讯 `getMatchScheduleList` JSONP → `data.anchorList[]` → `playInfo.streamInfo[]`：
**超清(3000p) / 高清(1500p) / 标清(800p)** 三档，**URL 不带 token → 永久有效**。
`http://` 需要升级成 `https://`（同主站 `app.js` 的做法），否则 HTTPS 页面会被混合内容拦。

### 1.3 社群弹幕 —— 当前不可用，**如实降级**

- B 站 `getDanmuInfo` 握手 → `-352`（IP 风控）；匿名握手 WebSocket → 立刻 `1006` 关闭。
  Node 直连同样结果 → 不是浏览器问题，是 IP 信誉问题。
- 腾讯直播弹幕：**没找到可用接口**（`barrage.garena.com` / `live-open.qq.com` / `barrage-proxy.qq.com` DNS 不存在）。
- 站内 `site/data/dm/*.json` 里**没有**决赛房的实时弹幕（CI 只烘焙已发布录像的弹幕）。

→ 页面保留完整的 B 站 WS 客户端（`assets/live-danmaku.js`，协议来自 `app.js` 里那份已验证实现），
运行时探测；**连不上就明说**，并降级为「站内历史弹幕基线」（9880 条提到两队的已过审评论样本）。

## 2. 胜率模型（可手算复核）

### 2.1 公式

```
① 单队 BO5 小局胜率   r = (胜 + 1) / (胜 + 负 + 2)          ← 加一平滑
② 对位单小局胜率     p = r_A / (r_A + r_B)                  ← Bradley-Terry
③ 赛前先验(0:0)      P₀ = p³(1 + 3q + 6q²),  q = 1 - p      ← BO5 净胜 3 局
④ 实时条件(a:b)      P  = Σ_{j=0}^{3-b-1} C(3-a-1+j, j) · p^(3-a) · q^j
⑤ 终局归一           3 胜 → 100%，对方 3 胜 → 0%
```

### 2.2 本场实算结果

| 输入 | 值 |
|---|---|
| GEN 本届 BO5 小局 | 6 胜 0 负 → `r = 7/8 = 0.875` |
| BLG 本届 BO5 小局 | 6 胜 1 负 → `r = 7/9 = 0.7778` |
| 对位单小局胜率 `p` | `0.875 / (0.875 + 0.7778) = 0.5294` |
| **赛前先验** | **`55.50% : 44.50%`**（与赛前预测的 55:45 吻合） |
| 比分 1:0 时 | **GEN 73.0%** |

### 2.3 ⚠️ 两条必须守住的设计纪律

1. **模型输入必须排除正在预测的那一场。**
   否则是循环论证：用「已经打到 1:0」去推「1:0 时的胜率」。
   实测不排除会让 `p` 从 `0.5294` 漂到 `0.5594`、先验从 55.50% 漂到 61.04%。
   → `tools/verify-match.mjs` 断言「页面实算的 p 与烘焙基线一致」守这条。

2. **`schedule.json` 里没有 `bMatchId` 字段**（只有 `id` / `title`）。
   识别「同一场」只能用**日期 + 两队**；
   早先用 `bMatchId` 比较会让 `undefined === undefined` 成立，把整届赛事排空。

## 3. 数据更新链路

- 跟赛页**运行时自己从镜像读 `schedule.json`** 并按 `updatedAt` 挑最新 → 不需要重新部署站点。
- `site/data/final-baseline.json` 是**兜底快照**（远端全挂时用），
  由 `tools/bake-baseline.mjs` 生成，**已接入 CI**（`refresh-data.yml` 里排在 `bake.mjs` 之后、
  合规门禁之前 —— 门禁会连它一起扫）。

```powershell
node tools/bake-baseline.mjs     # 重新烘焙基线
```

## 4. 验收

```powershell
node tools/verify-match.mjs       # 跟赛页专有断言（24 条）
node tools/verify.mjs             # 主站（102 条）
node tools/verify-public.mjs      # 线上
node tools/shot-match.mjs         # 截图（data/shots/final-{desktop,mobile}.png）
```

`tools/verify-match.mjs` 的判据（**不依赖数据年龄**）：

- 五个区块齐全、记分牌有对阵信息、对比表有数据行、解读有内容、推导链已展开
- 比分**带来源标注**；要么是数字，要么明确标为「未获取」（**不编造**）
- 胜率恒在 `[0,1]`；`3:0→100%`、`0:3→0%`；随领先局数**单调不减**；`0:0` 等于模型先验
- 页面实算的 `p` 与先验 **== 烘焙基线**（同源数据、且已排除本场）
- **面板渲染文本屏蔽词命中数 = 0**（唯一来源 `site/assets/abuse-words.js`）
- 腾讯源给出 ≥2 档清晰度
- `final.html` **不引** `assets/app.js`（不碰主播放器逻辑）
- 移动端无横向溢出

> `3:3` 是物理上不可能的状态（先到 3 局就结束），不纳入概率网格。

## 5. 合规

- 屏蔽词过滤复用 `site/assets/abuse-words.js`（**唯一来源**，28 词），浏览器与 Node 同规则。
- 跟赛页**没有新的裸渲染路径**：热词、里程碑、实时弹幕全部过 `safeText()`，
  命中即丢弃；渲染后再由验收扫一遍确认命中数为 0。
- CI 的合规门禁 `tools/scrub-danmaku.mjs --check` 会递归扫 `site/data/*.json`，
  `final-baseline.json` 也在内。

## 6. 已知边界

| 边界 | 说明 |
|---|---|
| 比分有 0~20 分钟延迟 | 源是 CI 每 20 分钟烘焙的赛程快照，不是秒级源；页面上标注了来源与更新时间 |
| 实时弹幕当前不可用 | B 站 IP 风控（-352）；已如实降级为历史基线 |
| 腾讯静态记分牌边缘滞后 | 同一份文件不同边缘给的版本不同；页面只把它当备选 |
| 胜率模型是「系列赛层」的粗粒度模型 | 不建模选手状态、阵容、BP、场地；页面把它叫「概率条」而不是「预测」，并展示推导链让用户自己判断 |
| 对手强度未量化 | 站内数据没有统一评级口径，所以只陈述对手名单，不编「谁更强」 |
