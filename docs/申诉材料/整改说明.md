## 〇、这一版改了什么（第二版被驳回的真实原因）

第二次申诉被驳回，理由是「内容**仍然**违反」。查下来根因不在页面，而在**数据层**：

1. 11-02 的整改只做了两件事：页面运行时过滤谩骂词 + 烘焙时**对新抓的弹幕**过滤。
2. 但 `tools/bake.mjs` 有一条**缓存短路**：`site/data/dm/{cid}.json` 已存在就直接 `continue`，
   既不重抓、**也不再过滤**。这些文件是 2026-10-25 / 10-29 写的，早于 11-02 的词表
   → 原始谩骂文本一直躺在公开数据文件里。
3. 弹幕数据文件本身是**公开可批量下载**的（仓库公开，站点 `data/dm/*.json` 直接可取）。
   平台审核读的是文件内容，不是页面 DOM —— 运行时过滤只挡 DOM，**挡不住 JSON**。
4. CI 每 20 分钟烘焙并把 `site/data` 推回公开仓库，于是**每天**都能重新读到同一批原文
   → 反复判不合规、反复撤回。

**这一版的修法**：把过滤下沉到数据层，并让 CI 再没有机会把脏数据推上去。

| 改动 | 位置 | 作用 |
|---|---|---|
| 新增数据层清洗工具 | `tools/scrub-danmaku.mjs` | 遍历 `site/data` 全部 JSON：弹幕条目命中→整条丢弃，其它字符串命中→等长打码；`--check` 只检查并用退出码报结果 |
| 烘焙前先清洗 | `tools/bake.mjs`（新增 `[0/4]` 步骤） | 覆盖缓存短路留下的旧文件，每轮烘焙都保证数据层干净 |
| CI 合规门禁 | `.github/workflows/refresh-data.yml` | 提交前跑 `node tools/scrub-danmaku.mjs --check`，有残留则 job 失败、**不提交** |
| 自动化断言 | `tools/verify.mjs` | 新增「数据层无屏蔽词原文（site/data 全部 JSON）」 |
| 一次性清洗（已执行） | 提交 `eaebcf9` | 清洗 126 个文件、丢弃 1157 条含屏蔽词弹幕（占清洗前弹幕总量 0.37%）；线上部署与仓库镜像均已复核为 **0 命中** |

> 清洗规则与页面运行时**同源**：词表唯一来源是 `site/assets/abuse-words.js`，
> Node 侧由 `tools/abuse-words.mjs` 读取同一份，两边不会不同步；
> 纯 ASCII 短词（tm / nm / sb）按**词边界**匹配，不会误伤「letme」「TMWBG」等选手名与队名。

## 一、站点性质

LPL-TV 是一个**面向英雄联盟赛事的技术型聚合播放器**（非腾讯官方站点）：

- 播放的是**腾讯 LPL 官方公开直播/点播地址**与 **B 站官方公开视频**，本站只提供播放器与界面层；
- **不存储、不转存、不二次分发任何视频文件**，仓库里也没有任何视频文件；
- 赛事信息（赛程、比分、录像目录）来自腾讯 LPL 公开接口；
- 弹幕为 B 站公开评论的转载，展示前做**个人信息脱敏**与**粗俗谩骂词过滤**（运行时过滤 + 数据层清洗双重）；
- 无用户注册、无付费、无广告、无抽奖、无诱导分享、无用户数据采集。
